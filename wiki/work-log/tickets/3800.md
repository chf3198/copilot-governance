# #3800 — Self-anneal: guard Epic-completion bundling drift (per-child baton traceability)

> **Source**: github:issue/3800 | **state: OPEN** | **Labels**: type:epic, status:backlog, priority:P1, area:governance, phase-gate:research-first, self-anneal:tier-3
> Mirror of `gh issue view 3800` (derived; edit the GitHub item, not this page).

## Body

## Trigger (self-anneal, Tier-3 — surfaced by live operation)

Completing Epic #2345 exposed a recurring governance defect: an Epic can be driven to CLOSED and its
children marked closed **in one bundled step** — reconciled together — **without each child carrying
its own per-child baton evidence** (an independent `## CONSULTANT_CLOSEOUT` + `## GitHub Evidence
Block`). This violates *one branch = one ticket = one PR* and the per-ticket baton contract, and it
**hides skipped role-workflow steps**: a child can read as "done" while never having independently
traversed Manager→Collaborator→Admin→Consultant.

**Evidence of prevalence:** a first-cut advisory detector (shipped in this Epic's Phase-0, see below)
finds **~640 existing closed children** across historical Epics (#1298, #1308, …) that lack their own
closeout/evidence. This is endemic, not a one-off — a standing guard is justified.

## Goal

New Epic-completion and child-closure paths must **degrade gracefully with an actionable advisory**
when a child is closed without independent baton evidence, and (after a shadow period) **block** an
Epic close that bundles un-evidenced children. No silent bulk closure. G1 non-negotiable.

## Phase 0 — shipped in this filing (advisory detector, reuse-first)

- `scripts/global/epic-child-baton-traceability.js` — pure `auditEpics()` core + advisory CLI.
  Invariants: **EB1** closed child of closed Epic lacks CONSULTANT_CLOSEOUT; **EB2** lacks GitHub
  Evidence Block; **EB3** closed Epic has an open child. Advisory-first (always exit 0).
- `scripts/global/epic-child-baton-traceability.spec.js` — 8/8 green, incl. a #2345-family regression
  (post-remediation → zero warnings).
- Validated: 0 warnings for the reconciled #2345 family; ~640 warnings across the historical corpus.

## Acceptance Criteria

- [x] AC1: Advisory detector + spec shipped and green (Phase-0, reuse the `accountable-team-verify` advisory pattern).
- [ ] AC2: Wire the detector into `governance-verify.js` as an advisory section (default-on, non-blocking), mirroring the ownership advisory (#2345 AC3).
- [ ] AC3: Emit an actionable remediation hint at Epic-close time (Manager/Admin baton path) naming the un-evidenced children.
- [ ] AC4: Shadow-period metric (false-positive rate over the corpus); promote EB1/EB2/EB3 from advisory to a hard Epic-close gate only at < 2% FP.
- [ ] AC5: (Scoped, optional) historical backfill plan for the ~640 pre-existing instances — deterministic, additive, dry-run default; NOT required to close the guard, tracked as a separate child.
- [ ] AC6: Docs — `docs/howto/` note + `role-baton-routing.instructions.md` cross-reference to the per-child evidence requirement.

## Scope

In scope: the detector, its wiring, the close-time hint, the promotion metric, docs. Historical
backfill is scoped as an optional child (advisory value stands without it).
Out of scope: forcing a literal separate git worktree per child for already-delivered code (the
reconcile-to-complete disposition remains valid when per-child evidence is present).

## Hard gate for Phase-1

Promotion of any invariant from advisory to blocking requires the AC4 shadow metric and a
cross-model consensus review (≥ 2 distinct free-cloud families) on the false-positive analysis.
