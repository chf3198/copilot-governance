## Body

#3810 fixed ONE Stop gate (`check_uncommitted`) that false-blocked on the parked feat/3026 checkout's
intentional ~764-path standing drift. Critical analysis **confirmed a second, independent gate with the
same blind spot** — `classify_internal_conflict`'s catch-all `worktree-drift` blocks on ANY dirty tree
— and traced the pattern to a **systemic root cause**: governance Stop-gates independently read RAW
`git status --porcelain` as a proxy for "this session did work," with no shared session-attribution
substrate and no prevention, so each new gate re-introduces the false positive (whack-a-mole; #2005,
#3054, #3810 were all reactive point-fixes).

This Epic **researches the root cause, ratifies a shared session-attributable gate substrate, fixes the
confirmed live blocker, and ships a recurrence meta-gate + advisory→shadow→blocking enforcement model**
so the whole CLASS is closed, not just the next instance. Full 7 ACs + phased plan + research grounding
(OPA Gatekeeper dryrun/warn/deny, alert-fatigue suppression, git dirty-tree detection, systemic-vs-point
fix) in `wiki/work-log/epic-3811/manager-scope.md`.
